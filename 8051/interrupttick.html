为什么必须写 last = now？

错误思路：只判断绝对时间

if(time0IntNum >= 500)
{
    P10 = !P10;
}

一旦 time0IntNum 到 500，以后的 501、502、503……全部仍然满足条件，于是 LED 会疯狂翻转。

正确思路：比较时间差

if(now - last >= interval)
{
    last = now;
    P10 = !P10;
}

触发后把 last 更新到当前时间，差值立即回到 0 附近，开始新的计时窗口。

进阶：无符号整数溢出为什么还能工作？

下面用 8 位无符号整数演示（0～255）。真实项目可能是 16 位或 32 位，道理一样。

now0
last0
差值（模 256）0
说明普通模式

例如：last = 250，之后 now 溢出到 4。按无符号 8 位模运算：

(4 - 250) mod 256 = 10

所以“经过了 10 个 tick”仍然可以算对。

阻塞延时 vs 非阻塞定时

阻塞 delay

delay_ms(500);
P10 = !P10;

CPU 500ms 内主要在“等待”，主循环其它任务难以及时执行。

非阻塞

if(now - last >= 500)
{
    last = now;
    P10 = !P10;
}

CPU 只做一次快速比较，剩余时间可以扫描按键、串口、刷新数码管。

它其实已经是“简易多任务调度”的雏形

if(now - lastLed >= 500) {
    lastLed = now;
    LedTask();
}

if(now - lastKey >= 20) {
    lastKey = now;
    KeyScan();
}

if(now - lastDisplay >= 5) {
    lastDisplay = now;
    DisplayRefresh();
}

同一个系统 tick，可以同时服务多个不同周期的任务。以后学习 STM32 的 HAL_GetTick()、SysTick、FreeRTOS Tick、软件定时器时，你会再次看到同样的思想。
