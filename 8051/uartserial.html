51 单片机串口通信，是怎么“把一个字符变成电平”发出去的？

不要把串口理解成“printf 神奇地把字发给电脑”。真正的过程是：CPU 把 8 位数据写入 SBUF → UART 硬件自动加起始位/停止位 → 按波特率逐位从 TXD 发出 → 发送结束后 TI 置 1。

关键：UART 是单片机里的专用硬件。CPU 只需要“交数据”和“看状态标志”，位级时序由 UART 外设完成。

4. 两个核心寄存器：点击 bit，可以观察含义变化

T2CON = 0x34 = 0011 0100

从 bit7 到 bit0：

SCON = 0x50 = 0101 0000

T2CON=0x34 的核心结果
RCLK=1、TCLK=1：接收和发送都选择 Timer2 作为波特率发生器。TR2=1：Timer2 开始运行。C/T2=0：内部时钟定时方式。
SCON=0x50 的核心结果
SM0=0、SM1=1：串口方式1；REN=1：允许接收；TI=0、RI=0：初始没有“发送完成/接收完成”事件。

5. 为什么 TH2/RCAP2H=0xFF、TL2/RCAP2L=0xDC 对应 9600？

TH2 = RCAP2H = 0xFF;
TL2 = RCAP2L = 0xDC;

高 8 位和低 8 位拼成：

0xFFDC = 65500

Timer2 从 65500 一直向上数到 65535，再溢出。所需计数次数：

65536 - 65500 = 36 次

65500
16位重装值
36
到溢出的计数次数
9600 baud
12T + Timer2 波特率
公式（本教程当前条件）：
Baud = Fosc ÷ [32 × (65536 - RCAP2)]

代入：11,059,200 ÷ (32 × 36) = 9600。

为什么 TH2/TL2 也要一起赋值？ RCAP2H/L 是“以后每次溢出时自动装回去的值”；TH2/TL2 是“现在计数器从哪里开始”。两组都初始化成 0xFFDC，第一次和之后每一次周期都一致。

8. 把你的初始化代码串成一条完整因果链

T2CON  = 0x34;
TH2 = RCAP2H = 0xff;
TL2 = RCAP2L = 0xdc;
SCON = 0x50;

char putchar(char c)
{
    SBUF = c;
    while(!TI);
    TI = 0;
    return c;
}
  1. SCON=0x50：UART 进入方式1，并允许接收。
  2. RCAP2=0xFFDC：规定 Timer2 每次溢出后从 0xFFDC 重新开始数。
  3. T2CON=0x34：启动 Timer2，并把 TX/RX 波特率时钟都切到 Timer2。
  4. 当执行 SBUF=c，数据交给 UART。
  5. UART 自动输出 Start → D0…D7 → Stop。
  6. 9600 baud 表示每秒 9600 个“位时间”；每 bit 约 104.17 µs。
  7. 8N1 一帧 10 bit，所以理论上连续发送大约 960 字节/秒（未考虑软件间隔）。
  8. 发送完成后硬件令 TI=1，while 循环退出。
  9. 软件执行 TI=0，为下一次发送做准备。
这版 putchar 是阻塞式发送。 在字符没发完之前，CPU 卡在 while(!TI);。初学阶段很好理解；以后做实时任务时，可以改成“串口中断 + 环形缓冲区”的非阻塞发送。
